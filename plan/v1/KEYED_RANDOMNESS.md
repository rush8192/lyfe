# Keyed Randomness and Random-Address Stability

Status: authoritative v1 randomness contract; initial domain assignments, manifest hash, and golden vectors are frozen by `RNG-100`

Sources: [technology decisions](TECHNOLOGY.md), [simulation loop](SIMULATION_LOOP.md), [world execution and ownership](WORLD_EXECUTION_AND_OWNERSHIP.md), [entity identity and storage](ENTITY_IDENTITY_AND_STORAGE.md), [rule-pack authoring and compilation](RULE_PACK_AUTHORING_AND_COMPILATION.md), and [persistence and replay](PERSISTENCE_AND_REPLAY.md).

# Purpose

Define one deterministic source of authoritative simulation randomness whose results depend only on explicit stable simulation facts. Random outcomes must not depend on worker count, worker completion order, dense row position, collection enumeration, client observation, logging, or whether an unrelated mechanic made another draw.

# Decision summary

- Implement and version the counter-based `Philox4x64-10` algorithm from Random123 inside `Lyfe.Simulation`.
- Store one 128-bit root simulation seed per world.
- Address every draw through a permanent `RandomDomainId`, three domain-defined unsigned 64-bit coordinates, and an explicit sample index.
- Maintain a reviewed random-domain registry with permanent numeric IDs and coordinate schemas; never use enum position, string hash, object hash, dense slot, worker number, or call count.
- Expose typed `Raw64`, exact bounded-integer, fixed-point Bernoulli, stable-rank, weighted-choice, and simple keyed-binomial operations. Authoritative code never receives a mutable random stream.
- Use integer-only conversions and canonical candidate ordering. Floating-point distribution helpers are excluded from authoritative simulation.
- Save the root seed, RNG algorithm ID, RNG schema version, and any gameplay ordinals needed to name recurring events. Stateless draw results and a global stream cursor are not save state.
- Treat any change to the algorithm, domain ID, address schema, or conversion rule as a replay-affecting simulation-version change.
- Keep cosmetic and security randomness outside authoritative simulation domains.

# Why a counter-based generator

A conventional PRNG advances mutable state. Adding a draw, changing iteration order, splitting work among workers, or observing one path conditionally can shift every later result. Avoiding that shift with one stream per entity still creates stream lifecycle, save, and cross-entity interaction problems.

A counter-based generator is a deterministic function:

```text
randomBlock = F(rootSeed, semanticAddress)
```

It has no mutable cursor. The same address always returns the same block, and unrelated addresses do not affect one another. This directly matches LYFE's stable IDs, phase snapshots, replay goals, and parallel worker model.

`System.Random`, including a seeded instance, is prohibited in authoritative simulation. Microsoft explicitly does not guarantee the same sequence across major .NET versions. Cryptographic platform RNG APIs are used only to create a root seed when the user does not provide one; they are not used during deterministic simulation.

# Generator primitive

V1 pins:

```text
algorithmId = "philox4x64-10-random123-v1"
counterWords = 4 × UInt64
keyWords = 2 × UInt64
outputWords = 4 × UInt64
rounds = 10
```

The implementation copies the published Random123 constants and word ordering exactly:

```text
M0 = 0xD2E7470EE14C6C93
M1 = 0xCA5A826395121157
W0 = 0x9E3779B97F4A7C15
W1 = 0xBB67AE8584CAA73B
```

Illustrative algorithm pseudocode:

```text
Philox4x64_10(counter, key):
    repeat 10 rounds:
        (hi0, lo0) = UInt64MultiplyHighLow(M0, counter.word0)
        (hi1, lo1) = UInt64MultiplyHighLow(M1, counter.word2)

        counter = (
            hi1 XOR counter.word1 XOR key.word0,
            lo1,
            hi0 XOR counter.word3 XOR key.word1,
            lo0)

        unless final round:
            key.word0 = unchecked(key.word0 + W0)
            key.word1 = unchecked(key.word1 + W1)

    return counter
```

C# multiplication uses `UInt128` to obtain the high and low halves of a 64-by-64-bit product. Addition is explicitly unchecked modulo `2^64`; conversions, word order, and endianness at serialization boundaries are explicit. The implementation does not wrap `System.Random` or inherit from it.

The Random123 reference implementation is the compatibility oracle. Before use in a world, the C# implementation must match frozen known-answer vectors generated by the reference for zero, all-one, patterned, and project-selected seed/counter inputs.

# Root seed

```text
RootRandomSeed:
    low: UInt64
    high: UInt64
```

The setup protocol accepts a canonical 32-hex-digit seed or asks the server to generate one. A generated value comes from `System.Security.Cryptography.RandomNumberGenerator`, is immediately stored as the world's root seed, and is shown/exported in canonical hexadecimal form. A human-friendly world name is not silently converted into a seed in v1.

The canonical text form is exactly 32 lowercase hexadecimal digits: `high` as 16 digits followed by `low` as 16 digits, with leading zeroes and no prefix or separators. Binary save and protocol schemas carry the two explicitly named fixed-width fields; they never serialize the native in-memory byte layout of the struct. Parsers may accept uppercase input for convenience but always emit the canonical lowercase form.

The seed is gameplay state, not a secret. Philox is a simulation PRNG, not a cryptographic primitive, and must never generate authentication tokens, password material, externally unique IDs, or other security-sensitive values.

# Random-address model

Every public draw takes this logical address:

```text
RandomAddress:
    domainId: RandomDomainId       // stable nonzero UInt32
    coordinate0: UInt64
    coordinate1: UInt64
    coordinate2: UInt64
    sampleIndex: UInt64
```

`sampleIndex` maps to one of the four output words and a 32-bit block index:

```text
blockIndex = sampleIndex / 4
lane = sampleIndex % 4
require blockIndex <= UInt32.MaxValue

counter.word0 = (UInt64(domainId) << 32) OR UInt32(blockIndex)
counter.word1 = coordinate0
counter.word2 = coordinate1
counter.word3 = coordinate2
key = (rootSeed.low, rootSeed.high)

Raw64(address) = Philox4x64_10(counter, key).word[lane]
```

This mapping is injective over the supported address space. It does not compress a variable tuple through a collision-prone hash. More than roughly `17 billion` samples for one semantic event is invalid configuration rather than wraparound.

Gameplay code supplies a semantic base address with `sampleIndex = 0`. The selected typed operation owns any consecutive sample indices needed for rejection or repeated trials; callers cannot assign another meaning inside that operation's sample range. Independent conceptual decisions use different domains or coordinates rather than hand-incrementing `sampleIndex`. Direct nonzero sample addressing is confined to the randomness module and frozen compatibility tests.

## Domain registry

`RandomDomainId` values live in an explicit generated registry owned by the simulation compatibility layer:

```text
RandomDomainDefinition:
    numericId
    stableName
    coordinate0Meaning
    coordinate1Meaning
    coordinate2Meaning
    allowedOperation
    introducedRngSchemaVersion
```

Rules:

- Numeric IDs are explicitly assigned, never inferred from source/enum order.
- An assigned ID is never reused, even after a mechanic is removed.
- Renaming a display label does not change its ID.
- Each domain defines the exact meaning of all three coordinates and whether roles are ordered or symmetric.
- Unused coordinates are zero.
- Stable `UInt32` pairs may use an explicitly documented injective `Pack32(high, low)` coordinate.
- A domain needing more semantic coordinates must introduce a stable stored ordinal/ID, split the operation into separately named domains, or prove a bounded injective packing. It must not call `GetHashCode`, concatenate ambiguous strings, or truncate a stable ID.
- Rule-pack IDs such as `ExposureId`, `ReactionId`, and `ResourceId` are coordinates under their pinned rules manifest, not new RNG domains.

The active/tombstoned ID-and-key lock, assignment workflow, and registry compatibility hash follow [RULE_PACK_AUTHORING_AND_COMPILATION.md](RULE_PACK_AUTHORING_AND_COMPILATION.md). RNG domains remain engine compatibility vocabulary rather than tunable scenario data.

## Occurrence ordinals

Ticks naturally distinguish most recurring organism decisions. A persistent ordinal is required when the same semantic event may occur repeatedly without a unique tick-based address or when its outcome must remain attached to a committed lifecycle event. Existing examples include:

- successful reproduction count for the next cooldown jitter;
- species speciation/evolution revision and autonomous evaluation ordinal;
- command replay order for command-originated creation;
- generation repair/attempt ordinal where world generation may retry.

Only canonical commit advances a persistent ordinal. A rejected intent, failed tick, debug preview, explanation query, or client observation cannot advance it.

# Typed random operations

Authoritative subsystems receive a narrow `ISimulationRandom` value API. They do not receive seed words, Philox blocks, or mutable generator objects.

## Raw word

`Raw64` is available only inside the randomness module and carefully reviewed stable-rank code. Gameplay code should use a typed conversion so rounding and bounds are centralized.

## Fixed-point Bernoulli

Probabilities use `RatioQ` in `0..1,000,000`:

```text
BernoulliDecision:
    probabilityQ
    rawWord?               // absent at exact 0 and 1 endpoints
    threshold?             // absent at exact endpoints
    triggered

Bernoulli(address, probabilityQ) -> BernoulliDecision:
    require 0 <= probabilityQ <= 1_000_000
    if probabilityQ == 0: return Decision(triggered = false)
    if probabilityQ == 1_000_000: return Decision(triggered = true)

    threshold = floor(UInt128(probabilityQ) * 2^64 / 1_000_000)
    rawWord = Raw64(address)
    return Decision(probabilityQ, rawWord, threshold,
                    triggered = UInt128(rawWord) < threshold)
```

The endpoint behavior is exact. Intermediate probabilities differ from the authored rational probability by less than one part in `2^64`, far below the `RatioQ` resolution. The raw word and the exact authored `probabilityQ` may be retained in a death or decision explanation record.

## Uniform bounded integer

Use deterministic rejection rather than `% bound` alone:

```text
UniformBelow(baseAddress, exclusiveUpper):
    require exclusiveUpper > 0
    fullRange = UInt128(1) << 64
    acceptanceLimit = fullRange - (fullRange % exclusiveUpper)

    sample = baseAddress.sampleIndex
    loop:
        value = Raw64(baseAddress with sampleIndex = sample)
        sample = checked(sample + 1)
        if UInt128(value) < acceptanceLimit:
            return value % exclusiveUpper
```

This is the simple unbiased v1 conversion. A multiply-high alternative is considered only if profiling identifies integer range conversion as a real bottleneck and it remains golden-vector compatible at the typed-operation boundary.

## Stable random rank

Contention and tie-break rules that intentionally rotate advantage use:

```text
rank = (Raw64(address), canonicalLogicalKey)
```

The random word sorts first; the complete stable logical key breaks the extraordinarily unlikely raw tie. Worker position and input enumeration never participate.

## Weighted choice

```text
WeightedChoice(baseAddress, candidates):
    eligible = candidates filtered to eligible entries with weight > 0
    ordered = eligible sorted by canonical candidate key
    require candidate keys are unique
    require ordered is not empty
    require every weight > 0
    total = checked UInt128 sum of weights
    require total <= UInt64.MaxValue
    target = UniformBelow(baseAddress, UInt64(total))

    cumulative = 0
    for candidate in ordered:
        cumulative += candidate.weight
        if target < cumulative: return candidate
```

Candidate-set construction is deterministic and consumes no randomness. The eligible positive-weight set, including any candidate-set fingerprint stored in an intent or explanation, is defined only after ineligible and zero-weight candidates are removed. Adding either kind cannot change the result.

## Keyed binomial

The simple authoritative baseline evaluates at most the admitted whole opportunity ceiling and performs one Bernoulli per opportunity:

```text
KeyedBinomial(baseAddress, trials, probabilityQ):
    require baseAddress.sampleIndex == 0
    successes = 0
    threshold = CompileBernoulliThreshold(probabilityQ)
    for each needed Philox block covering trial ordinals 0..<trials:
        block = RawBlock(baseAddress coordinates, blockIndex)
        for each in-range lane/trialOrdinal in block:
            if EvaluateBernoulliLane(block[lane], threshold).triggered:
                successes += 1
    return successes
```

The scalar reference maps trial ordinal `i` to sample index `i`; the implementation computes each four-word Philox block once and uses its four lanes locally rather than recomputing that block for each lane. This is a local evaluation detail, not mutable RNG state. Current authored ceilings are small enough for this per-trial reference distribution. A different binomial algorithm is not introduced until representative profiling shows this operation materially limits tick capacity; changing its exact draw mapping is a replay-breaking RNG-schema change.

## Without-replacement selection

Sort candidates canonically. At selection position `i`, use a domain whose third coordinate is `i`, select with `UniformBelow(remainingCount)`, remove by deterministic index, and repeat. Do not shuffle a dense store in place or use its physical order.

# Distribution-specific rules

- Brownian direction selects from the versioned 256-entry antipodal integer direction table with `UniformBelow(256)`.
- Brownian magnitude selects through its separately versioned integer magnitude table/curve under a distinct domain.
- Reproduction jitter draws one inclusive integer in the compiled `0..maximumJitterHours` range when the cooldown is scheduled. The result is then stored in `reproduction_not_before_tick`; later checks make no draw.
- Each positive intrinsic death cause uses its own domain/address and is evaluated even if another cause already succeeded, preserving the complete risk record.
- Predation kill draws are role-ordered `(predatorId, preyId)`; symmetric mechanics explicitly canonicalize the pair instead.
- Deterministic reproduction, allocation gates, resource arithmetic, and mandatory maintenance never gain hidden random draws.
- Remainder randomness changes only which eligible claimant receives indivisible residual quanta. It does not change total granted matter or bypass priority/capacity rules.

# Phase and parallelism rules

- An evaluator can call keyed operations in any iteration order because every address is complete.
- Random addresses may contain stable IDs and logical ordinals only, never dense rows, chunk IDs, worker IDs, partition IDs, thread IDs, wall time, or collection counts that change with layout.
- Resolving a shared conflict may generate stable ranks in the owner/reducer or in workers; both must use the same address schema and stable snapshot.
- A worker may recompute the same address and receive the same value. It cannot reserve or consume a draw.
- A failed phase/tick discards outputs but does not require RNG rollback.
- Evaluation previews must use a separate preview domain or report distributions/expected ranges. They may not invoke the future authoritative address and reveal a pending outcome to the player.

# Persistence, replay, and compatibility

The world root and save metadata contain:

```text
RandomCompatibilityState:
    rootSeed
    algorithmId
    rngSchemaVersion
    rngDomainManifestHash
```

There is no global cursor or per-worker stream state. Persistent gameplay ordinals remain with the entity/subsystem that owns their semantic event.

Load and replay require an implementation of the exact `algorithmId`, `rngSchemaVersion`, and registered-domain manifest. If unavailable, the world is incompatible; silently upgrading it would change its future. Adding a new unused domain is compatible with earlier outcomes only through an explicitly compatible manifest/version policy; changing an existing numeric ID, coordinate meaning, packing, sample assignment, conversion, or candidate canonicalization requires a new RNG schema version.

Rule changes may retain an RNG schema to support common-random-number balance comparisons when the same mechanic and address still have the same meaning. The rules hash remains separate and still determines whether the save itself is otherwise compatible.

# Diagnostics and observability

A debug-only random audit may record:

```text
RandomAuditEntry:
    tickOrBoundary
    domainId
    coordinates
    sampleIndex
    rawWord
    typedOperation
    operationInputs
    result
    owningEntityOrGroup
```

The audit is not authoritative state and cannot affect evaluation. It supports filters by domain/entity/tick and a strict mode that flags unexpected duplicate semantic addresses from different call sites. Expected reevaluation of the same decision must return the same result and can be explicitly marked.

Player explanations expose authored probability, relevant factors, and realized outcome where authorized. Raw words are normally diagnostic-only; death records may retain them because the existing causality contract calls for the exact draw.

# Failure behavior

- Unknown domain, invalid coordinate packing, sample-block overflow, zero range, invalid probability, excessive weighted total, or unordered/duplicate candidate key is a deterministic invariant/configuration failure.
- RNG implementation/vector mismatch prevents server startup or world load.
- No failure falls back to `System.Random`, wall-clock entropy, or another algorithm.
- Random audit failure faults validation; it never substitutes a new draw.

# Required tests

- C# Philox matches frozen Random123 known-answer vectors and an independent scalar reference.
- Output is identical in checked/unchecked build configurations where specified, on supported x64/ARM64 platforms, and across little-endian serialization round trips.
- Every registered domain has a unique nonzero ID, complete coordinate schema, and stable generated manifest.
- Same address returns the same result; changing domain or any coordinate changes the address without touching other outcomes.
- `Bernoulli` endpoints are exact and intermediate thresholds match UInt128 golden calculations.
- `UniformBelow` stays in range, matches golden rejection cases, and is statistically smoke-tested for awkward small bounds without using modulo-only conversion.
- Weighted selection is invariant under candidate enumeration and fails duplicate canonical keys.
- Keyed binomial matches the per-trial Bernoulli reference exactly.
- Brownian, death, predation, reproduction jitter, mutation/autonomy, world generation, and remainder fixtures use registered domains and remain invariant under dense-row order and supported worker counts.
- Save/load retains seed/algorithm/schema and semantic ordinals; continuation produces the same future draws.
- Static analysis or an architecture test rejects `System.Random`, `Random.Shared`, cryptographic RNG, nondeterministic GUID creation, and wall-clock entropy inside authoritative simulation projects except the approved root-seed factory boundary.
- Client queries, explanations, logging, metrics, and preview compilation consume no authoritative random address.

# Scientific and platform basis

Counter-based generators were designed for parallel simulations: independent keyed transformations of counters avoid sequential generator state, parallelize naturally, and the Random123 families passed the TestU01 BigCrush suite in the authors' evaluation. LYFE uses the published ten-round 4×64-bit Philox variant and freezes its own compatibility vectors rather than depending on a platform package: [Salmon, Moraes, Dror, and Shaw](https://www.thesalmons.org/john/random123/papers/random123sc11.pdf), [Random123 project](https://random123.com/), [official Random123 Philox reference source](https://github.com/DEShawResearch/random123/blob/main/include/Random123/philox.h), and [official known-answer vectors](https://github.com/DEShawResearch/random123/blob/main/tests/kat_vectors).

The platform RNG is deliberately excluded because Microsoft documents that `System.Random` is not guaranteed to keep the same implementation or seeded sequence across major .NET versions: [Microsoft .NET `Random` documentation](https://learn.microsoft.com/en-us/dotnet/api/system.random?view=net-10.0#notes-to-callers).
